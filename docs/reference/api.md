# HTTP API

Base path `/api/v1`. JSON, `snake_case` keys. Field-level schemas are generated by FastAPI: http://localhost:8000/docs (disabled when `APP_ENV=production`). Conventions: [api_rules.md](../standards/api_rules.md).

## Auth

Send the operator key as header `X-API-Key` matching env `API_KEY` on these routes:

- `POST /clinics/discover`
- `POST /clinics/{id}/signals:detect`
- `POST /clinics/{id}/score`
- `POST /clinics/{id}/enrich`
- `PUT /scoring-config`

GET list, detail, signals, scoring-config, and health stay open so the dashboard can read.

If `API_KEY` is empty and `ALLOW_UNAUTHENTICATED` is `false`, those mutating routes return **503** `API_KEY_NOT_CONFIGURED`. If the header is missing or wrong, they return **401** `UNAUTHORIZED`.

The browser uses the same-origin frontend BFF, which injects `X-API-Key` from server-only runtime configuration on writes.

## Rate limits

Redis-backed per-IP limiter shared by every API replica. Window is 60 seconds. Limit is `RATE_LIMIT_PER_MINUTE` (settings default **30**; local compose often **60**).

Limited paths:

- `/api/v1/clinics/discover`
- `PUT /api/v1/scoring-config`
- any path ending in `/signals:detect`
- any path ending in `/enrich`

`POST /clinics/{id}/score` is **not** rate-limited.

Over the limit: **429** `RATE_LIMITED` with `Retry-After`. Trust `X-Forwarded-For` only via `RATE_LIMIT_TRUSTED_PROXIES`. See [deploy](../how-to/deploy.md).
If Redis is unavailable, limited requests fail closed with **503** `RATE_LIMIT_UNAVAILABLE`.

## Endpoints

All mutating pipeline jobs below run **synchronously** and return **200**, not 202.

### Health

| Method | Path | Auth | Success |
|--------|------|------|---------|
| GET | `/health/live` | no | 200 `{ "status": "ok" }` |
| GET | `/health/ready` | no | 200 `{ "status": "ok" }` if Postgres and Redis answer; otherwise 503 `{ "status": "degraded" }` |
| GET | `/health` | no | Legacy readiness alias |

### Clinics

```bash
curl -sS -X POST http://localhost:8000/api/v1/clinics/discover \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $API_KEY" \
  -d '{"query":"dentist in Lisbon"}'
```

```json
{ "ingested": 60, "created": 48, "updated": 12 }
```

List ranked clinics:

```bash
curl -sS "http://localhost:8000/api/v1/clinics?priority=HOT&q=Sorriso&sort=-score&page=1&page_size=20"
```

Query params: `q`, `state`, `priority` (`COLD` \| `WARM` \| `HOT` \| `IMMEDIATE`), `min_score`, `max_score`, `has_website`, `signal_type`, `sort` (`-score` \| `score` \| `name`), `page` (1-based), `page_size` (default 20, max 100). `min_score` must be `<= max_score` or the API returns **422**.

```json
{
  "data": [
    {
      "id": "f0c9a1b2-0000-4000-8000-000000000001",
      "name": "Clínica Sorriso",
      "city": "Lisboa",
      "state": "Lisboa",
      "score": 130,
      "priority": "HOT",
      "growth_probability": 78
    }
  ],
  "page": 1,
  "page_size": 20,
  "total": 42
}
```

Detail:

```bash
curl -sS http://localhost:8000/api/v1/clinics/f0c9a1b2-0000-4000-8000-000000000001
```

Unknown id → **404** `CLINIC_NOT_FOUND`.

Detect / score / enrich (replace `{id}`):

```bash
curl -sS -X POST http://localhost:8000/api/v1/clinics/{id}/signals:detect \
  -H "X-API-Key: $API_KEY"

curl -sS http://localhost:8000/api/v1/clinics/{id}/signals

curl -sS -X POST http://localhost:8000/api/v1/clinics/{id}/score \
  -H "X-API-Key: $API_KEY"

curl -sS -X POST "http://localhost:8000/api/v1/clinics/{id}/enrich?force=false" \
  -H "X-API-Key: $API_KEY"
```

Detect skip: `skipped: true` with `skip_reason` `"Clinic has no website"` (or the crawl error). Prior signals are kept.

Enrich skip: `skip_reason` `"Inputs unchanged"` unless `force=true`.

LLM failure → **502** `ENRICHMENT_FAILED` (generic client message; raw provider text stays in server logs).

### Scoring config

```bash
curl -sS http://localhost:8000/api/v1/scoring-config
```

`PUT` body and `rescore`: [tune scoring](../how-to/tune-scoring.md). Concurrent write → **409** `SCORING_CONFIG_CONFLICT`.

## Errors

Envelope:

```json
{
  "error": {
    "code": "CLINIC_NOT_FOUND",
    "message": "Clinic f0c9a1b2-0000-4000-8000-000000000001 not found",
    "details": null
  }
}
```

| HTTP | `code` | When |
|------|--------|------|
| 401 | `UNAUTHORIZED` | Missing or wrong `X-API-Key` |
| 404 | `CLINIC_NOT_FOUND` | Unknown clinic id |
| 409 | `SCORING_CONFIG_CONFLICT` | Concurrent config write; retry |
| 422 | `VALIDATION_ERROR` | Bad body or query (`min_score` > `max_score`, band gaps, …) |
| 429 | `RATE_LIMITED` | Shared Redis limiter |
| 429 | `DISCOVERY_QUOTA_EXCEEDED` | Google Places quota |
| 502 | `DISCOVERY_UNAUTHORIZED` | Bad Places key |
| 502 | `ENRICHMENT_FAILED` | LLM call failed |
| 503 | `API_KEY_NOT_CONFIGURED` | Empty `API_KEY` and not unauthenticated |
| 503 | `RATE_LIMIT_UNAVAILABLE` | Redis unavailable; cost controls fail closed |
| 503 | `DISCOVERY_UNAVAILABLE` | Places upstream down |
| 500 | `INTERNAL_ERROR` | Unexpected; `details.request_id` only |

Discovery failures: missing key or transport → `DISCOVERY_UNAVAILABLE`; HTTP 403/401 from Places → `DISCOVERY_UNAUTHORIZED`.

## Idempotency

- Discover upserts by Google `place_id`.
- Detect on success replaces that clinic's signal set. On crawl failure, prior signals stay.
- Score and enrich overwrite the single row per clinic.
